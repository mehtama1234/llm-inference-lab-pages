model math

Terms inside one model step.

Token x_t
integer ID at position t Text after tokenizer conversion. The model sees IDs, not words. Prompt cost, context fit, prefix-cache reuse, and output length are all token-count problems. See math first principles.
Embedding h_t = E[x_t] A table lookup from token ID to vector. After lookup, all later work is vector arithmetic. See attention vectors.
Dot product a . b = sum_i a_i b_i Coordinate-by-coordinate agreement between two vectors. Attention scores and logits are built from many dot products. See QKV.
Matrix multiply Y = X W Many dot products arranged as one operation. GPU efficiency depends heavily on these shapes and batches. See batching.
Query Q = H W_Q The current token's learned read request. During decode, usually one new query reads cached K/V rows. See attention math.
Key K = H W_K A learned address label for each visible token. Stored in KV cache because future decode steps need it. See KV cache math.
Value V = H W_V The learned payload that attention mixes. Also stored in KV cache; values are the content read after weights are computed.
Softmax exp(s_i) / sum_j exp(s_j) Converts scores into positive shares that sum to one. Used for attention weights and next-token probabilities. See softmax.
Logit z = h W_vocab^T A raw score for a candidate next token. Temperature, top-k, and top-p reshape logits before token choice. See sampling.
cache math

Terms that make inference a memory problem.

Prefill prompt tokens -> initial K/V The first pass over the prompt before the first output token. Long prompts raise TTFT. See cache reuse.
Decode one new token per step The repeated loop that streams output tokens. Decode pressure shows up as ITL and output latency. See latency.
KV cache K_old, V_old Stored keys and values for previous visible positions. Saves recomputation but consumes memory that grows with active tokens. See KV formula.
KV bytes layers * 2 * positions * kv_heads * head_dim * bytes The memory bill for stored attention history. This explains why loaded model fit is not the same as traffic fit.
PagedAttention logical block -> physical block KV allocation in reusable fixed-size blocks. Reduces wasted cache memory for uneven request lengths. See paged KV.
Prefix cache same token prefix -> reuse K/V Reuse of completed cache blocks for identical token prefixes. Works only when token IDs and settings match. See prefix cache.
serving math

Terms that connect runtime behavior to user-visible results.

Arrival rate lambda How fast requests enter the system. If arrivals exceed service, queues grow. See queueing.
Service rate mu How fast the server can complete useful work under a workload. The overload boundary is measured, not guessed.
Admission estimated_KV <= room The decision to let a request enter active work. Protects memory and latency by rejecting or delaying work that cannot fit. See admission.
TTFT arrival -> first token Time to first streamed output token. Mostly exposes queue and prefill pressure.
ITL token_i -> token_(i+1) Inter-token latency during streaming. Mostly exposes decode step time and scheduler pressure.
p95 95% below this latency A tail-latency measurement. Prevents average latency from hiding bad user experience.
Throughput tokens / second Aggregate useful output or processed token rate. Useful for capacity, but incomplete without TTFT, ITL, and p95.
training math

Terms in the Unsloth and adapter lane.

LoRA rank rank(A B) <= r The dimensional limit on the adapter update. Small rank lowers trainable parameters. See LoRA math.
QLoRA quantized W + trainable A B Frozen low-bit base with trainable adapters. Lowers training memory, but quality still needs evaluation. See QLoRA.
SFT loss - sum log P(target token) Penalty for assigning low probability to target completions. Moves the adapter toward the training examples. See SFT loss.
Reward r(completion) A score assigned to sampled output. Useful only if the reward measures the behavior we actually want.
GRPO group c_1 ... c_G Several completions sampled for one prompt and compared by reward. Tiny runs prove API/artifacts, not durable reasoning. See GRPO.
claim words

Words we use to keep results honest.

Mechanism proof why it should work A mathematical or systems explanation of the method. Example: KV cache avoids recomputing old K/V rows.
Workflow proof it ran end to end Evidence that setup, script, artifact, and reload path work. Example: tiny Unsloth adapter archive and fresh reload.
Quality proof behavior improved Requires held-out evaluation, baseline comparison, and repeatability. Not provided by tiny setup-only runs.
Speed proof same workload, same host Runtime comparison under controlled conditions. For us, this is locked until the matched TGI/vLLM host archive returns.
honest public claim = mechanism explanation + exact experiment evidence + explicit non-claims + source links + reproducible artifact boundary
