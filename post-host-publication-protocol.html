post-host publication protocol

A returned host archive changes the public site only after import, contract, and fairness gates pass.

This protocol starts after the external NVIDIA host sends back the return archive. It defines the local intake sequence, the five public pages that may change, and the claim rule for pass, diagnostic fail, and workload mismatch.

Import is a gate, not a formality.

The returned archive must prove three things before any metric table is rebuilt: the copied files are intact, the archive members are safe, and both runtime result files satisfy the same workload contract.

public edit order

Only five public pages should move from locked to measured after a passing return.

result-provenance.html first edit Record whether the return is missing, diagnostic, failed, mismatched, or measured. Why first: every later page depends on provenance labels.
tgi-vllm-locked-comparison.html second edit Replace locked placeholders only if both runtime rows and fair gate pass. Why second: this is where TTFT, p95, completion latency, token rate, and errors belong.
capstone-readiness-checklist.html third edit Move the same-host runtime proof gate from locked to satisfied, or keep it locked with a failure reason. Why third: readiness is a gate ledger, not a metric table.
capstone-serving-decision.html fourth edit Publish a bounded recommendation only if the comparison gate passes and the metric rubric supports the interpretation. Why fourth: the final decision must inherit all earlier boundaries.
next-runs-board.html fifth edit Replace the P0 host proof with post-host followups only after the P0 gate resolves. Why fifth: second-order experiments need the host baseline.
allowed outcomes

The final public claim has three legal shapes.

Measured bounded winner allowed if fair gate passes The site may say which runtime won on this model, host, workload, request file, client, and generation bound. It still may not claim a universal runtime ranking.
Measured no-winner allowed if inconclusive The site may say the comparison returned but did not justify a winner because error, variance, saturation, or setup instability dominated. It should then name the next correction run.
Diagnostic locked result required if gate fails The site may publish host failure evidence, missing files, logs, or mismatch findings. It must keep the production recommendation locked.
