first-principles study path

Read the lab in the order the system actually runs.

This page turns the public writeups into a study path. Start with the model's arithmetic, then cache memory, then runtime scheduling, then adapter training, then source claims, then the capstone serving decision.

orientation

The order matters because each later problem depends on an earlier object.

Serving runtime behavior makes little sense until token work, attention work, and KV memory are clear. Adapter training makes little sense until the difference between changing weights and serving fixed weights is clear. The capstone only makes sense when every claim has a source, a mechanism, and an experiment boundary.

model arithmetic -> cache memory -> runtime scheduling -> adapter behavior -> source claims -> experiment claims -> serving decision
Do not start with runtimesTGI and vLLM are wrappers around token work, KV memory, queues, and metrics.
Do not start with benchmarksMetrics mean something only after the measured phase is named: prefill, decode, queue, or memory.
Do not merge claim typesWorkflow proof, speed proof, and quality proof answer different questions.
route

The recommended reading path.

01 Glossary Read math-glossary.html. Question: what concrete object does each word name? Exit when token, logit, KV bytes, TTFT, LoRA rank, and speed proof are distinct in your head.
02 Big Picture Read big-picture-inference.html and math-first-principles.html. Question: what overall problem are we solving? Exit when you can say why inference is repeated conditional probability under memory and waiting constraints.
03 Attention Read attention-math.html. Question: how does one token read previous tokens? Exit when Q, K, V, mask, softmax, and logits are tied to formulas.
04 KV Cache Read kv-cache-math.html. Question: why does faster decode create a memory wall? Exit when you can derive the KV byte formula and explain PagedAttention without changing attention math.
05 Serving Runtime Read serving-runtime-math.html. Question: how do queues, batching, and admission turn model math into user latency? Exit when TTFT, ITL, p95, throughput, and overload each point to a different part of the system.
06 Adapter Training Read adapter-training-math.html. Question: how does Unsloth/LoRA change behavior without full fine-tuning? Exit when workflow proof and quality proof are separate.
07 Source Map Read paper-math-map.html. Question: what object does each source change? Exit when PagedAttention, HF cache/quantization, TGI, NVIDIA, JetStream, and Unsloth are one connected chain.
08 Experiment Claims Read experiment-claim-matrix.html. Question: what did each experiment prove, and what stayed locked? Exit when each run has an allowed claim and a non-claim.
09 Capstone Read capstone-serving-decision.html. Question: what evidence would let us choose a serving path? Exit when the matched TGI/vLLM host proof is clearly the remaining speed gate.
checkpoints

Use these checks to tell whether the first-principles thread is actually understood.

Attention checkExplain why softmax(QK^T/sqrt(d))V is a read operation over prior token vectors.
Cache checkExplain why KV cache is exact reuse, then show why it becomes a memory bill.
Serving checkExplain why high tokens/sec can still coexist with bad p95 latency.
Adapter checkExplain why W + A B can be much smaller than a full update.
Experiment checkGiven a run artifact, state the allowed claim and the locked claim.
Capstone checkState the exact same-host evidence needed before naming a TGI/vLLM winner.
finish line

The study path finishes when explanation, experiment, and claim boundary line up.

A strong final writeup should not read like a pile of papers or notebooks. It should read like one defended case: the math predicts where pressure comes from, the experiments test those pressures, and the claim says only what the evidence can carry.

finished public argument = first-principles mechanism + source-backed method + experiment artifact + measured result + explicit non-claim + next gate if the claim is still locked
