first-principles spine

A LoRA adapter is a small trainable change added to a frozen model.

Full fine-tuning changes the large base matrix W. LoRA keeps W fixed and learns a low-rank update BA. This is why the saved artifact can be small: it stores the learned update and config, not a second full model.

base layer: h = W x LoRA layer: h = W x + scale * B A x where: W is frozen A maps the input into r adapter coordinates B maps r adapter coordinates back to model width r is much smaller than the full matrix dimensions

reward optimization

GRPO adds a reward surface, so the first proof is whether that surface is valid.

GRPO samples completions, scores them, and moves the policy toward completions with better relative reward. Mathematically, this only helps if the reward separates desired behavior from bad behavior and if the model has enough training signal to move.

GRPO-style update: sample G completions for a prompt score each completion with reward functions compute relative advantage inside the group increase probability of completions with positive advantage keep the update bounded so the policy does not drift too far

What these Unsloth runs let us say now.

Allowed claim Colab plus Unsloth can run setup, train small LoRA SFT and tiny GRPO windows, save adapter artifacts, verify archives, and reload those adapters in a fresh GPU runtime.
Mathematical lesson Adapter training changes a small low-rank update, while serving optimization changes scheduling, batching, memory layout, and request admission. They answer different questions.
Locked claims No production serving speed claim, no vLLM/TGI claim, no GGUF/export claim, and no broad GRPO quality claim are unlocked by these short runs.
