reading key

Every formula is either arithmetic, bytes, waiting, training, or evidence.

If a formula changes arithmetic, it changes work. If it changes bytes, it changes fit and memory movement. If it changes waiting, it changes user-visible latency. If it changes trainable parameters, it changes adaptation cost. If it changes evidence, it changes what we can claim.

model formulas

One model step.

Embedding lookup 
h_t = E[x_t] + position(t)
x_t is a token ID; E is the embedding table. Text becomes vector state. Token count controls how many positions enter later work.
QKV projections 
Q = H W_Q
K = H W_K
V = H W_V
H is hidden states; W_Q, W_K, W_V are learned matrices. Queries ask what to read; keys label visible positions; values carry the payload to mix.
Attention 
O = softmax((Q K^T + mask) / sqrt(d_head)) V
d_head is head width; mask blocks illegal future reads. This is the read operation that makes prior token content affect the current token.
Stable softmax 
p_i = exp(s_i - max(s)) / sum_j exp(s_j - max(s))
s_i is a score. Subtracting max keeps numbers stable. Scores become positive shares that sum to one.
Logits 
z = h_last W_vocab^T
z has one score per vocabulary token. Generation policy turns these scores into the next output token.
cache formulas

Memory created by faster decode.

KV bytes 
KV bytes =
layers * 2 * positions * kv_heads * head_dim * active_sequences * bytes_per_number
The 2 is K and V. Positions include prompt and generated tokens. This is why concurrency, context length, output length, and precision determine traffic fit.
Available KV room 
KV room =
GPU memory - weights - workspace - activations - safety_margin
Weights loading successfully does not mean serving traffic fits. Admission limits must protect the remaining memory.
Paged lookup 
logical_position -> block_id + offset
block_table[request, block_id] -> physical_block
Attention needs logical order, not contiguous physical allocation. PagedAttention reduces wasted KV memory for dynamic request lengths.
Prefix hit 
cache hit if same token ids
+ same model/tokenizer
+ same cache settings
+ same block boundary
Similar text is not enough; the token prefix must match. Exact prefix reuse skips repeated prefill for shared prefixes.
serving formulas

Queues, latency, and admission.

Queue stability 
stable if lambda < mu
lambda is arrival rate; mu is measured service rate. If arrivals exceed service, queue wait and p95 grow.
TTFT 
TTFT =
queue_wait + validation + tokenization + prefill + first_decode_gap
Time from request arrival to first streamed token. Long prompts and queue pressure appear here.
ITL 
ITL_i = time(token_i) - time(token_(i-1))
Inter-token latency during streaming. Decode scheduler pressure and KV read cost appear here.
Admission gate 
admit if:
input_tokens <= max_input_tokens
input_tokens + output_cap <= max_total_tokens
estimated_KV_after <= KV_room
active_sequences_after <= sequence_cap
Each condition protects a different capacity limit. Admission is math around finite GPU memory and service rate.
training formulas

Adapter behavior change.

LoRA update 
y = x (W + (alpha / r) A B)
W is frozen; A and B are trainable rank-r factors. Small adapters can move behavior with far fewer trainable parameters.
LoRA parameter count 
full update: d_in * d_out
LoRA update: r * (d_in + d_out)
r is the adapter rank. Lower trainable count lowers optimizer memory and makes notebook runs practical.
SFT loss 
loss = - sum_t log P(y_t | prompt, y_1 ... y_(t-1))
Penalty for assigning low probability to target training tokens. Moves adapter behavior toward training examples; quality needs held-out proof.
GRPO-style group 
sample completions c_1 ... c_G
score rewards r_1 ... r_G
advantage_i = normalize(r_i within group)
Updates favor completions that score better than peers for the same prompt. Tiny runs prove workflow, not durable reasoning.
claim formulas

Evidence boundaries.

Speculative payoff 
useful if:
accepted_target_tokens_saved > draft_overhead + verification_overhead
Draft model proposals help only when enough tokens are accepted. Acceptance rate is the center of the claim.
Fair runtime claim 
same model
+ same tokenizer/template
+ same workload and request ids
+ same host and GPU
+ same client
+ same metrics
Runtime comparisons are not portable unless the evidence boundary is fixed. This is why the matched TGI/vLLM host run remains the capstone gate.
Honest public claim 
claim =
mechanism
+ artifact
+ measurement
+ source
+ explicit non-claim
The non-claim is part of the result, not a footnote. It keeps mechanism proof, workflow proof, quality proof, and speed proof separate.
