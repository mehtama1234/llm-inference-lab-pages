decision tree

The public writeup has three possible outcomes.

Pass condition
Both runtime contracts pass and the fair gate accepts the workload match. claim
A bounded TGI/vLLM result is allowed for this model, host, workload, and client. pages
Update provenance, locked comparison, readiness, decision, next runs, and completion audit.
Fail condition
A host, server, model, or client stage fails but diagnostics return. claim
Publish the failure as setup or runtime evidence. lock
Keep the speed winner and production recommendation locked.
Mismatch condition
The two runtime legs used different model, tokenizer, prompts, host, GPU, client, or generation limits. claim
Do not compute a winner from unmatched numbers. next
Rerun the matched campaign with corrected metadata.
