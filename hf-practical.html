A minimal Transformers run is text, token IDs, tensors, generated IDs, then text again.

This trace does not pretend the library is magic. It shows the objects created by each line and the point where the returned sequence switches from prompt IDs to newly generated IDs.

tokenizerTurns text pieces into integer token IDs using the model vocabulary.
modelUses loaded weights to append new token IDs one step at a time.
prompt echo`generate()` returns prompt IDs plus new IDs, so output text should usually slice after the prompt length.

completed output-decoding trace

Output text is a choice made after generation, not the raw thing the model returns.

The model returns IDs. Practical code has to decide which IDs are prompt echo, which IDs are the answer, where the answer stops, and which control tokens should stay hidden from the user.

prompt echoThe returned row starts with the original prompt IDs. Those IDs are usually dropped before printing the answer.
answer IDsGenerated content starts at the prompt length and continues until a stop token or output cap.
special tokensStop and role markers control generation and formatting. They are not ordinary answer words.

completed chat-template trace

Chat messages become one prompt string before the model sees them.

A chat template is not display formatting. It inserts role markers, message boundaries, and an assistant-start marker before tokenization. Those inserted pieces become real token IDs.

role markersSystem, user, and assistant labels are written into the prompt so the model knows which span it is reading.
token overheadTemplate markers use context window space and add prompt work during prefill.
reusable prefixA stable system message and its boundary tokens can be reused across requests when prefix caching is enabled.

completed cache-setting trace

KV cache changes what the model has to read on each decode step.

The user-visible sequence still grows one token at a time. The setting decides whether the model reuses stored key/value rows or forwards the whole growing sequence again.

cache onPrefill stores K and V rows. Later decode steps pass one newest token and read the stored rows.
cache offNo stored rows are reused. Each decode step forwards the full sequence built so far.
static cacheFixed cache shape can help repeated decode optimization, but unused reserved positions still cost memory.

completed precision-loading trace

Precision changes fixed weight memory before any request runs.

A model has learned weight numbers. Precision decides how many bytes store each number. Smaller storage can make a model fit and leave more room for KV cache, but speed and output quality need separate tests.

dtypeFloating loads such as fp16 and bf16 use `torch_dtype` during `from_pretrained()`.
8-bit / 4-bitQuantized loads use `BitsAndBytesConfig`; this changes module storage, not just a display label.
fit checkWeights, runtime overhead, safety margin, and KV room all have to fit in VRAM together.
