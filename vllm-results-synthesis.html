vLLM pressure is where token math becomes queue math.

These Colab L4 runs used a pinned vLLM CUDA setup with Qwen/Qwen2.5-0.5B-Instruct. The result is a bounded capacity story: active sequence slots, arrival rate, output length, prompt length, max batched tokens, prefix caching, and streaming each moved a different term in the serving equation.

first-principles spine

A serving runtime manages scarce slots, scarce KV memory, and arriving work.

vLLM does not change what the transformer computes. It changes how many requests can be active, how KV history is stored in blocks, how token work is batched, and how queued requests wait. The math is the old token loop plus a queue.

for each request: work = prefill(prompt_tokens) + decode(output_tokens) memory = weights + KV(prompt_tokens + generated_tokens) + runtime overhead queue grows when: arrival_rate * expected_work_per_request > service_capacity Paged KV helps by: allocating KV in blocks close to actual sequence length instead of requiring one contiguous reserved span

arrival knee

After slots were raised to 16, arrival rate became the control variable.

A stable system has arrival work below service capacity. The measured vLLM run found a useful knee: throughput peaked around 30.303 req/sec, while 40 req/sec crossed the 1 second queue-watch line.

knee interpretation: 20 req/s -> lower queue, lower throughput 30.303 req/s -> best observed throughput 40 req/s -> queue watch crossed production rule: admission should cap traffic before the queue-watch point, not after users feel it

prompt and output shape

Prompt length hits prefill; output length holds decode slots longer.

The same request rate can be easy or hard depending on shape. Long prompts delay the first token because prefill is larger. Long outputs keep a request active for more decode steps and can build a queue even if the prompt is unchanged.

prefix cache

Prefix caching helped only when the starting tokens were exactly reusable.

A prefix cache hit means the server can reuse KV rows for a repeated prompt beginning. Similar content later in a prompt is not enough; the token prefix must match.

streaming clock

Streaming changed first visible output, not the total compute obligation.

Streaming is a user-experience clock. It lets the client see the first chunk before the full answer is done. It does not make the later decode tokens free.

bounded conclusion

What these vLLM runs let us say now.

Allowed claim On this Colab L4 vLLM setup, active sequence slots, arrival rate, output length, prompt shape, max batched tokens, prefix caching, and streaming each moved distinct capacity or latency terms.
Mathematical lesson The saturation knee is not one number. It depends on request shape and scheduler gates: slots decide how many sequences run, output length decides how long they stay, and arrival rate decides whether waiting accumulates.
Locked claim These results do not choose vLLM over TGI. The final runtime winner remains locked until the matched TGI and vLLM host replay returns from the same GPU, model, request file, client, and metric contract.
