proof sketches

The mechanisms work only when their mathematical assumptions hold.

This page gives compact proof sketches for the lab's core mechanisms. A proof sketch is not a formal theorem. It is the minimum reasoning needed to know why a method should work, what metric should move, and what condition would make the method fail.

reading rule

Every optimization has a conserved object.

The trick is to find what does not change. KV caching keeps the same keys and values while avoiding recomputation. Paging keeps logical token order while changing physical memory layout. Quantization keeps a close approximation of weights while changing storage. LoRA keeps the base model fixed while changing a low-rank slice of the function.

optimization proof pattern: 1. name the original computation 2. name the transformed computation 3. show which output, order, or decision is preserved 4. identify the resource term that shrinks 5. state the assumption required for preservation
EquivalenceThe transformed computation gives the same result, as with exact KV cache reuse.
ApproximationThe transformed computation is close enough, as with quantized weights.
TradeoffThe transformed system improves one metric while worsening another, as with batching and queue wait.
attention scaling

Scaled dot-product attention prevents dimension from controlling softmax sharpness.

If q_i and k_i have mean 0 and variance 1: score = q dot k = sum_i q_i k_i Var(score) = d_k standard deviation(score) = sqrt(d_k) scaled score = score / sqrt(d_k) standard deviation(scaled score) = 1
why it worksWithout scaling, larger head dimension makes raw scores spread out. Softmax then becomes too sharp, so one token can dominate before the model has learned useful routing. Scaling keeps score magnitude in a range where probabilities can still move.
what should moveThe distribution over visible tokens should avoid accidental saturation from dimension alone. The model can still learn sharp attention when useful.
break conditionIf the assumed score distribution is already normalized by architecture or training dynamics, the simple variance argument is incomplete; the empirical check is attention entropy and stability, not the formula alone.
KV cache equivalence

KV caching is exact because previous token hidden states do not change during autoregressive decode.

At decode step t: K_past = [k_1, ..., k_{t-1}] V_past = [v_1, ..., v_{t-1}] recompute path: K_all = f_K(h_1, ..., h_t) V_all = f_V(h_1, ..., h_t) cache path: K_all = concat(K_past, f_K(h_t)) V_all = concat(V_past, f_V(h_t))
why it worksCausal masking means later tokens cannot change the hidden states already computed for earlier positions. If the model weights and prompt prefix are unchanged, the old K/V vectors are identical to what recomputation would produce.
resource shiftCompute shrinks because old K/V projections are not recomputed. Memory grows because old K/V tensors must be retained for every active layer and token.
break conditionCache reuse is invalid if the prefix, tokenizer, template, weights, adapter, position scheme, or attention mask changes. It is also not a free speedup when memory bandwidth becomes the bottleneck.
paged memory equivalence

PagedAttention preserves attention inputs by replacing address arithmetic with lookup arithmetic.

contiguous KV lookup: address(token_i) = base + i * stride paged KV lookup: block = floor(i / block_size) offset = i mod block_size address(token_i) = block_table[block] + offset * stride
why it worksAttention consumes a sequence of K/V vectors in logical token order. That logical order can be reconstructed from a block table even when physical memory is non-contiguous.
resource shiftInternal fragmentation shrinks because the server allocates blocks closer to actual sequence growth instead of reserving one large future slab.
break conditionThe lookup table adds metadata and indirection. Paging helps most when fragmentation, shared prefixes, or variable-length requests are the binding constraint; it is less decisive when compute kernels or client overhead dominate.
queue stability

Batching helps throughput only while arrival work stays below service capacity.

Let lambda = request arrival rate Let E[S] = average service work per request Let mu = available service work per second stable if: lambda * E[S] < mu waiting grows sharply as utilization rho = lambda * E[S] / mu approaches 1
why it worksBatching increases effective service capacity by giving the GPU more parallel work per step. That lowers average service time only if batching overhead and memory pressure do not erase the gain.
what should moveThroughput and occupancy should rise. TTFT or tail ITL may rise if prefill bursts and decode streams compete in the same queue.
break conditionAt high utilization, small increases in arrivals create large increases in waiting. A system can have impressive tokens/sec and still violate user latency goals.
quantization error

Quantization is safe only when output error stays smaller than the decision margin.

quantized layer: y = x W y_hat = x W_hat error_y = y - y_hat = x (W - W_hat) logit order is preserved between tokens a and b if: |error_logit_a - error_logit_b| < original_margin(a, b)
why it worksIf the quantized matrix is close to the original in the directions the activation vector uses, the downstream logits stay close. The likely next token often remains the likely next token.
resource shiftWeight bytes and sometimes bandwidth shrink. Dequantization or less efficient kernels can add compute overhead, so fit improvement is not automatically latency improvement.
break conditionWhen the model is choosing between tokens with tiny logit margins, small reconstruction errors can flip the decision. Quality must be measured on task prompts, not inferred from byte savings.
low-rank adaptation

LoRA works when the needed parameter change is low rank or well-approximated by low rank.

full fine-tune: y = x(W + Delta W) LoRA: Delta W = B A B shape: output_dim x r A shape: r x input_dim rank(Delta W) <= r trainable parameters: r * (input_dim + output_dim)
why it worksIf task adaptation mainly needs a small number of directions in activation space, low-rank factors can express the useful movement without updating every weight independently.
resource shiftOptimizer state and gradients shrink because training touches adapter matrices rather than the full base model.
break conditionIf the task requires many independent changes across the full matrix, a small rank cannot express the needed update. Raising rank, target modules, or data quality becomes part of the experiment.
group-relative reward

GRPO-style training depends on reward differences inside a completion group.

For prompt x, sample completions y_1 ... y_g reward r_i = R(x, y_i) group baseline b = mean(r_1 ... r_g) advantage A_i = r_i - b updates increase probability of completions with A_i > 0 and decrease probability of completions with A_i < 0
why it worksThe group baseline removes prompt-level difficulty and keeps the signal focused on which completion was better relative to siblings for the same prompt.
what should moveReward distribution, format adherence, and invalid reward rate should move before any broad reasoning claim is made.
break conditionIf the reward function is brittle, hackable, or mostly constant within groups, the advantage signal is weak or misleading. Then training optimizes the reward artifact, not the intended behavior.
speculative decoding

Speculative decoding helps only when accepted draft work replaces enough target work.

expected useful saving: E[accepted_tokens] * target_step_cost extra cost: draft_cost + target_verification_cost + coordination_overhead speedup condition: E[accepted_tokens] * target_step_cost > extra cost
why it worksA cheaper draft model proposes several future tokens. The target model verifies them in a way that preserves the target distribution when the algorithm is implemented correctly.
what should moveTarget decode calls per emitted token should fall enough to beat draft and verification overhead. Acceptance rate is the central metric.
break conditionIf the draft is too inaccurate, too slow, or expensive to coordinate, accepted tokens do not cover the added work. Long prompts and small output caps can also leave too little decode phase to recover overhead.
