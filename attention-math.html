attention math deep dive

Attention is a learned routing table built from dot products.

This page slows down the core transformer calculation. It explains what Q, K, V, masks, softmax, heads, logits, sampling, prefill, decode, and KV cache mean mathematically, then connects that math to the serving experiments.

core idea

A transformer layer lets each token choose what previous tokens to read.

The model does not store grammar rules as text. It stores matrices. Those matrices turn each token vector into questions, labels, and content. A token asks a question with its query vector. Every visible token answers with a key vector. The dot product decides how strongly the current token reads each value vector.

Attention(Q, K, V) = softmax((Q K^T + mask) / sqrt(d_head)) V
Q is the read request For the current position, Q says what pattern this position is looking for.
K is the address label For each visible position, K says what kind of information that position can offer.
V is the payload V is the vector content that gets mixed into the current position after the weights are computed.
vector basis

Before attention, every token is just a vector plus position information.

Tokenization turns text into integer IDs. The embedding table maps each ID to a vector. Position information tells the model where that token sits in the sequence. After that, each layer updates every position's vector.

x_t = token id at position t h_t = E[x_t] + position(t)

The vector is not a human-readable meaning. It is a list of learned coordinates. Matrix multiplication rotates, stretches, and combines those coordinates into new coordinate systems where the next operation becomes easier.

Q K V

Q, K, and V are three learned projections of the same hidden states.

H has shape: tokens x model_dim Q = H W_Q K = H W_K V = H W_V scores = Q K^T / sqrt(d_head)
Projection Each matrix creates a different view of the same token states. This lets the model separate "what I need", "what I contain", and "what content I should pass forward".
Similarity For query i and key j, the score is q_i . k_j. A large score means the learned coordinates line up. The current token will read more from that prior token after softmax.
Scaling The division by sqrt(d_head) keeps dot products from growing too large as vector width increases. Without scaling, softmax can become too sharp early, making gradients and probabilities harder to control.
Causal mask For generation, position i cannot read j if j is in the future. The mask changes illegal scores to a very negative value before softmax, so future positions get almost no probability mass.
normalization

Softmax turns scores into a distribution over readable positions.

Scores can be any real numbers. Attention needs nonnegative weights that sum to one so it can make a weighted average of value vectors. Softmax performs that conversion.

stable_softmax(s_i) = exp(s_i - max(s)) / sum_j exp(s_j - max(s)) attention_output_i = sum_j stable_softmax(score_ij) * v_j
Why exponentials Exponentials make every readable score positive and amplify differences between scores.
Why subtract max Subtracting the largest score leaves probabilities unchanged but avoids huge exponentials.
Failure to watch If scores are too sharp, one token dominates; if too flat, the model mixes too much weakly relevant context.
multi-head attention

Multiple heads are parallel read patterns, not multiple minds.

A layer splits the hidden dimension into heads. Each head has its own Q/K/V projections and its own attention weights. The head outputs are concatenated and mixed back into the model dimension.

head_h = softmax(Q_h K_h^T / sqrt(d_head)) V_h multi_head = concat(head_1, ..., head_H) W_O
Why heads help Different projections let the same token position read different kinds of relationships at once. One head can route nearby syntax, another can route earlier entities, another can route formatting boundaries.
Why GQA/MQA matter Grouped-query and multi-query attention reduce the number of K/V heads stored. The query side can stay expressive while KV cache bytes shrink, changing the serving memory bill.
prefill and decode

The same attention equation has two very different runtime shapes.

Prefill shape Many prompt tokens enter together. The model computes Q, K, V, scores, and outputs for the prompt positions.
Decode shape One new token enters. Its query reads cached K/V rows for all visible previous positions.
Cache reason Past K/V rows are deterministic once computed, so storing them avoids repeating old projection work.
without cache over T generated tokens: prompt work + growing-prefix recomputation at each decode step with cache over T generated tokens: prompt prefill once + T one-token decode steps + KV memory growth
Why TTFT rises with prompt length The first output token cannot appear until prompt prefill has built the hidden state and initial KV cache. Long chat history, tools, and RAG chunks all increase this front-loaded work.
Why ITL is a decode metric After the first token, each later streamed token waits for another one-token decode step. That step reads weights and cached K/V, so it is often limited by memory movement and scheduler pressure.
next token choice

Logits are scores; decoding policy decides how scores become text.

The model ends a step with one score per vocabulary token. Softmax converts those logits into probabilities. The decoding policy decides whether to take the largest probability or sample from a shaped distribution.

p_i = exp(z_i / temperature) / sum_j exp(z_j / temperature) top-k: keep only k candidate tokens before renormalizing top-p: keep the smallest set whose cumulative probability reaches p
Greedy Always choose the largest probability. Repeatable, but can be brittle or dull.
Temperature Lower temperature sharpens choices. Higher temperature spreads probability across more candidates.
Stop condition The loop ends by stop token, stop string, max token limit, timeout, cancellation, or server policy.
