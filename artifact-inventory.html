inventory rule

An artifact is useful when it narrows uncertainty.

The lab now has many result files: Colab GPU measurements, Hugging Face traces, Unsloth adapter proofs, vLLM pressure probes, host readiness packets, source audits, and capstone gates. The mistake would be to treat all of them as equal evidence. They are not.

artifact strength = environment truth + fixed workload truth + metric truth + mechanism isolation + reproducibility proof - missing host or cloud gates - changed model/request/runtime variables

claim ledger

The same file can unlock one claim while leaving a larger claim locked.

Cache math Evidence can show that storing keys and values avoids recomputing prior token states. The larger serving claim needs concurrency and memory pressure.
Quantization Evidence can show memory fit. Latency needs kernel, batch, model-size, and output-shape timing. Quality needs task-specific comparisons.
Speculative decoding Evidence can show fewer target forward passes. Speed requires assistant overhead to be smaller than saved target work.
LoRA and Unsloth Evidence can show low-rank update artifacts and reload. Capability improvement needs held-out prompts and an explicit scoring contract.
Paged KV Evidence can show that block allocation improves active-sequence handling. Runtime choice needs a matched competitor and workload.
Batching Evidence can show higher GPU occupancy. User experience still depends on queue wait, TTFT, cancellation, and output length variance.
TGI versus vLLM The final winner is still locked. A fair claim needs both systems on the same host, same request replay, same model, and same metric contract.
Cloud serving Cloud runbooks prove setup boundaries. Performance claims wait for account, quota, deployment, endpoint health, and request replay results.
