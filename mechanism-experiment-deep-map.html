one problem

The big picture problem is bounded conditional generation under resource pressure.

A model turns a prefix into a next-token distribution. In a real serving system, many prefixes arrive at once, each prefix creates memory state, and every generated token repeats part of the same computation. The lab is trying to learn which constraint dominates: arithmetic, memory, scheduling, approximation error, or operations.

one generated answer = tokenize prompt + prefill all prompt positions + store K/V history + repeat decode until stop or output cap + stream tokens through a server + keep queue wait inside the user-facing budget optimization question: which term can be reduced without breaking the output claim?
MechanismA mathematical reason a method should change compute, bytes, or waiting.
ExperimentA controlled run that changes one variable while holding the claim boundary fixed.
Non-claimThe explicit statement that prevents a small run from becoming a broad runtime myth.
model math

Transformer and Hugging Face experiments start at the token loop itself.

Attention source
Attention Is All You Need. math object
softmax(QK^T / sqrt(d))V, a weighted read over prior token states. why it works
The model replaces a serial recurrence with learned similarity scores between all visible positions. experiment
Attention traces and first-principles pages check Q/K/V shapes, masking, softmax, and logits.
KV cache source
Hugging Face generation and optimization docs. math object
Stored K and V rows that are deterministic functions of earlier tokens. why it works
A fixed prior prefix has fixed K/V tensors, so decode can read history instead of recomputing it. experiment
HF cache strategy runs separate support, memory fit, compile compatibility, and latency.
Speculative decoding source
Hugging Face and vLLM speculative decoding references. math object
Expected accepted draft tokens per expensive target-model verification. why it works
If the draft model proposes tokens the target accepts, several decode steps can be verified together. experiment
HF speculative runs show target-call reduction, then keep end-to-end speed claims narrow.
memory math

Most serving improvements become obvious once every token is converted into bytes.

memory pressure = weight_bytes + active_KV_bytes + activations_and_workspace + runtime_overhead active_KV_bytes = layers * active_positions * kv_heads * head_dim * 2 * bytes_per_number
PagedAttention source
vLLM PagedAttention paper. math object
Logical token positions mapped through block tables to physical KV blocks. why it works
Attention requires correct logical order, not contiguous physical allocation, so block reuse reduces waste. experiment
vLLM pressure probes vary active slots, prompt length, output length, prefix reuse, and queue arrival.
Quantization source
Hugging Face bitsandbytes path and QLoRA. math object
w_hat = scale * code, replacing large stored weights with compact approximations. why it works
If output logits stay close enough in task-relevant directions, fewer bytes can improve fit or bandwidth. experiment
HF quantization results separate memory fit from generation latency and quality-preservation claims.
Prefix reuse source
vLLM prefix caching docs and local prefix-cache probes. math object
Identical token prefixes imply identical prefill K/V tensors under the same model state. why it works
The server can reuse completed prefix blocks instead of spending prefill work again. experiment
Prefix-cache probes must keep token IDs and chat template boundaries exact; similar text is not enough.
serving math

TGI, vLLM, TensorRT-LLM, and JetStream differ as policies around the same queue.

observed latency = queue_wait + prefill_time + sum(decode_step_time) + streaming_and_client_overhead stable service needs: arrival_rate * average_work_per_request < service_capacity
Continuous batching source
TGI architecture, launcher, and Transformers continuous batching references. math object
A time-varying active set of requests that share decode steps. why it works
Larger grouped GPU work can raise utilization while completed requests leave and new requests enter. experiment
The matched TGI/vLLM host run must report TTFT, completion latency, token rate, queue/stream evidence, and proof limits.
Runtime specialization source
NVIDIA inference optimization and TensorRT-LLM docs. math object
Repeated graph shapes, precision choices, kernels, communication, and build-time assumptions. why it works
A stable model/hardware path can pay a setup cost once, then reduce per-token overhead repeatedly. experiment
TensorRT-LLM belongs after the base host proof, when repeated traffic can justify build-payback measurement.
Cloud serving source
Google JetStream/GKE tutorials and deployment notes. math object
The same token loop wrapped by quota, accelerator topology, model storage, endpoint health, and rollout controls. why it works
It proves the serving path can exist under managed infrastructure and operational gates. experiment
JetStream/GKE runs should be treated as deployment evidence first, then benchmark evidence only after request replay returns.
training math

Unsloth belongs in the same map because adaptation is a constrained update problem.

LoRA source
LoRA paper and Unsloth SFT notebooks. math object
W' = W + BA with rank(BA) <= r. why it works
A task can require movement in a few important directions rather than a free change to every weight. experiment
Unsloth SFT mini-runs prove setup, adapter save, hashes, reload, and bounded inference behavior.
GRPO-style reward learning source
Unsloth GRPO reasoning notebooks and local reward-contract probes. math object
Grouped completions scored by a reward rule, then used to push the policy toward higher-scoring outputs. why it works
Relative scores can provide a learning signal without a single fixed target string for every prompt. experiment
Tiny GRPO runs prove workflow and reward-contract shape; held-out quality remains a separate gate.
Adapter serving source
Unsloth adapter artifacts plus runtime serving references. math object
Base forward pass plus adapter contribution on selected layers. why it works
The adapted model can change behavior without storing a full second model copy. experiment
Serving speed needs its own TGI/vLLM-compatible adapter run; training success is not latency proof.
what this unlocks

The meaty end-to-end goal is a causal story, not just a collection of benchmark numbers.

The public report should eventually say: this workload has this token shape; that shape creates this prefill, decode, KV, queue, and adapter pressure; these mechanisms target those pressures; these runs moved or failed to move the predicted metrics; therefore this bounded serving choice is defensible for this workload and no broader claim is made.
